Move face+

Onshape document Reference_Side_Features  |  Feature sheet, draft 2026-11-06 (FeatureScript 3083)

Offset faces in place toward (or away from) a reference you point at, instead of along whichever way each face's normal happens to point. Faces of surfaces with opposite normals all move the same way.

Dialog (toward a reference)

Schematic. Two sheets with opposite normals: the built-in Move face sends them in opposite directions; Move face+ sends both toward the reference.

Use it when / not when

Use it when
• the faces belong to surfaces whose normals are not consistent (or may flip after an upstream edit)
• you want “toward this point” to stay true whatever the normals do
• you need the moved faces and their boundary edges as named outputs		 Use something else when
• the face normals are reliable and you want the plain grow / shrink: the built-in Move face (Move face+ with no reference behaves the same)
• you need a different distance per face: one feature per distance

How it works

Move face+ runs the built-in offset face (opOffsetFace). For each body that owns selected faces it reads the reference's side once (signed distance from the reference to that body's selected faces), so every selected face of that body moves the same way. Faces are then offset in at most two operations: those moving along their normal and those moving against it.

Quick start

  1. Select the Faces to move.
  2. Pick a Side reference: a vertex, mate connector, edge, face or part clearly on the side you want to move toward.
  3. Type a Distance. Positive moves toward the reference.
  4. If it went the wrong way, change the Distance sign or untick/tick Move toward reference (the flip arrow).
  5. Optional: Reapply fillets if the faces carry fillets that must follow.

The one rule: the reference sets the direction

SituationResult
Reference given+Distance moves each body's faces toward it; the sign of the normals does not matter.
No referenceNative behaviour: +Distance moves along the normals. A solid's face normal points out of the material, so a solid grows.
Reference selected but unreadableAn error, never silently “no reference”.

Dialog parameters, outputs, limits

Dialog, in order

Faces to moveFaces only (no sketch or construction objects). Any mix of bodies; each body is handled on its own.
DistanceSigned length, default 25 mm (1 in); remembers the last value. Positive: toward the reference (without one: along the normals). Negative: the other way. 0: nothing moves.
Side referenceOptional, one pick: a part, face, edge, vertex or mate connector. Prefer a local mate connector or vertex on the side you mean; the side is read where the reference is closest to the faces.
Move toward referenceDefault on. On: toward the reference. Off: away from it. With no reference: along (on) or against (off) the normals.
Reapply filletsDefault off. Defillets the moved faces before the offset and fillets them again after (the built-in option).
Debug > Print detailsDefault off. Prints, per body, how many faces went along or against their normal.

Outputs (for Extract variables)

outputThe moved faces (followed through the offset, including faces the kernel had to split).
boundaryEdgesThe edges bounding the moved faces.
inputsThe selected faces. Standard keys such as modifiedFaces come from the producer library. Every key is published even at distance 0.

Examples

• Two sheets of opposite orientation, reference between them, Distance 1.5: both faces move 1.5 toward the reference (figure, right).
• A solid box, no reference, Distance 2: the faces grow 2 (native). Turn Move toward reference off to shrink.
• Same selection, reference on the far side of the part: the same faces move the other way, with no change to the Distance.

Limits

• One side decision per body, not per face: a body whose selected faces lie on both sides of the reference moves them all the same way. Per-face sides for solid faces are an open design question.
• The side is read from the signed distance at the closest point; a reference far from the faces (a far plane) can read ambiguously. Use a local point.
• Whether the kernel accepts a given offset (sharp corners, neighbouring faces) is the built-in offset face's call; its error is passed through.
• Not verified for this sheet: live results of the Reference_Side test group for Move face+ (no Onshape calls were made).
