Case pattern

Define case · Case · Close case  |  Onshape document Case_Pattern  |  Feature sheet, draft 2026-11-06 (feature v3)

Build a chain of features once, against named inputs, then run it again for each case, every case with its own selections and values. Think “apply to each” for the feature tree.

Test T1: one chain (boss, rim fillet, boss-edge fillet) built for case A, then run for B (25 mm, R3) and C (8 mm, R2) on different blocks.

Use it when / not when

Use it when
• the same feature chain applies to several places
• each place has its own selections and dimensions
• the chain edits existing geometry (fillet, move face) as well as making new		 Use something else when
• every repeat is a moved copy: Linear / Circular / Curve pattern
• only which entity changes: Query pattern (Evan Reese)
• different recipes per entity: Amalgamate (Derek Van Allen)

How it works: like a function

FeatureRoleWhat you do
Define casethe signatureName the inputs (selections) and values (numbers) that change per case, filled with case 1's choices.
(body)the functionOrdinary features after it, using the names (#top, #bossH). This is case 1.
Caseone call's argumentsOne per further case: a selection per input, a value per value. Runs nothing itself.
Close caseruns the callsLists the body and the Cases, runs the body once per Case, publishes each case's outputs.

Quick start

  1. Define case: name case 1; add Inputs (name + selection) and Values (name, type, value).
  2. Build the body as normal features, using #names in selections and expressions.
  3. Make a Query Variable “created by” a body feature for anything a later body feature must reach.
  4. Add one Case per further case: pick the Define case, name the case, fill the slots.
  5. Close case: pick the Define case, the body features, the Cases; add Outputs (a name and the query variable) you need later.
  6. Check the result: parts are named <case>_<output>; outputs are #B_rib, #C_rib...

Tips

• Switch features per case with a Boolean Value and a suppression expression (#pin); it is re-checked per case.
• Run more cases later: a second Close case (same Define case, body picked again) runs further Cases that may select geometry the first batch made.
• Keep the variable list short: every query variable name stays for the rest of the tree. Use short local names (_body, _edges) reused in every body; declare Outputs only for what a later feature uses.

Limits

• Not for sheet metal or derived features. Every rebuild runs the body once per case plus case 1.
• Cases run in order and see earlier results. A failed case cannot undo edits to existing geometry; only its new bodies are removed.
• Edits to existing geometry are verified for fillet and Move face. Chamfer, shell, draft and booleans into existing parts are untested.
• In a new Case the grey slot names stay blank until you press Update from Define case.
