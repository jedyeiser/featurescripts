Add variables for derive

Status: pushed to the workspace, compiled without errors, never run. Unverified: that a custom feature can build the other studio, that variables set by Variable features are visible in that context, and name autocomplete. Needs a user version of Variable_tools before other documents see it.

A Derived Part Studio brings geometry across, not variables. Put this feature in the source studio to list the variables the deriving studio should receive; Extract variables in the deriving studio then sets them again under the same names.

The source studio stores a map called exportVariables; the deriving studio reads it through Extract variables.

Use it when / not when

Use it when
• a studio derives from another and needs its dimensions
• no geometry carrier (a dummy part) is wanted		 Use something else when
• the value is a single measured or assigned variable: tick Export for derive in Variable +
• you need a query variable across the derive: not possible

How it works

StepWhereWhat
1source studioThis feature reads the current value of each name you list and merges them into the variable exportVariables (name to value).
2deriving studioAdd Derived as usual, then Extract variables with Get variables from a derived Part Studio ticked and the same studio picked.
3deriving studioEvery entry is set as an ordinary variable of the same name (#length); an existing one is overwritten.

Quick start

  1. In the source studio, create the variables (Variable, Variable +).
  2. Add Add variables for derive after them in the tree.
  3. Add an item per variable and type its name without #.
  4. In the deriving studio add the Derived feature, then Extract variables; tick Get variables from a derived Part Studio and pick the source.
  5. Check the notice: "Exporting N variable(s)..." (source), "Published N name(s)" (deriving).

The key rule

Values are snapshots at the feature's position: put it after the variables, and any variable edited later in the tree is not seen. Only ordinary values travel (numbers, lengths, angles, text, maps); queries and query variables cannot.

Add variables for derive, reference

Dialog parameters, outputs, limits

Dialog

VariablesList of items, labelled by name. Each item is one variable. Starts empty; the feature then only reports "Exporting 0 variable(s)".
Variable nameA variable set earlier in this studio, without the #. Variable-name autocomplete is enabled. Max 10000 characters. A name listed twice: the later one wins.

No units, bounds or other parameters. No preview.

Outputs

exportVariablesOne map variable in the source studio, name to value. Other producers merge into the same map (Variable + with Export for derive), so you can mix both.
In the deriving studioOne ordinary variable per entry, same name, set by Extract variables with description "From derived Part Studio"; also added to its optional manifest. A name that an Extract entry also publishes raises an error.

The two ways to export

ProducerUse for
Add variables for deriveVariables that already exist (including from other features); one place for the list.
Variable +, Export for deriveA variable made by Variable + itself; the tick adds it as it is created. Assigned, measured and Map values all qualify (Map: untested).

Limits

• Extract variables builds the source studio once more to read the map (one extra regeneration; it uses the studio's configuration).
• The studio configuration picked in the Derived Part Studio field is the one that is built (from code; not run).
• Not yet exercised: empty Sources list in Extract variables, configured studios, large maps.
