Extract variables

Document Variable_tools (FeatureScript 3083)  |  Feature sheet, draft 2026-11-06

Status: in live use (topsheet_surf, RD 20FOU 28, Design_Master); tracking tests 4/4 and region tests 6/6 (2026-09). The newer Get variables from a derived Part Studio option is pushed but not run.

One feature per block of the tree that turns what the block's features produced into named variables and query variables (a region, a cut, a chain end, the two largest faces) so later features pick them by name and keep working when the model changes.

Show highlights the published body and band cuts; "Published 6 name(s)."

Sources publish keys; entries turn keys into names. The derive input is new.

Use it when / not when

Use it when
• a block feeds many later selections
• a selection must be computed (region, chain end, largest N)
• names must survive upstream edits
• variables from a derived studio must be re-set here		 Use something else when
• you need one name for one click: a native Query variable
• the value is a measurement: Variable +

How it works

Our producers add their own keys; any feature offers output, outputFaces/Edges/Vertices and modified*. A key offered by one source is addressed by its bare name; by several, key@1, key@2... (the bare name then warns "ambiguous"). Published names are <prefix>_<name>.

Quick start

  1. Add Extract variables after the block; pick the block's features as Sources.
  2. Type a Prefix (box), press Add keys from sources.
  3. Delete entries you do not need; rename or retype the rest (Filtered, Closest to point, Region ...). Turn Show on to see them.
  4. Use the names (#box_body, or a query variable from the dropdown) later.
  5. To bring variables across a derive: tick Get variables from a derived Part Studio and pick the source studio.

The key rule

Keep a name with Hold (default: the entities present now, followed through edits that keep them), Track (also what later splits and merges make of them; it grows) or Evaluate on use (the producer's query re-run where it is used; rarely right). A merge onto a held edge loses it: use Track.

Outputs

#prefix_name for value entries; a native query variable prefix_name for query entries (it shows in later dialogs' query-variable dropdowns); variables from a derive; the optional manifest. Query variables cannot be removed once set: publish only what is used.

Limits

• Adding a second source turns bare output into output@n; entries with the bare name then warn. • "Body name contains" reads part names during regeneration and is untested. • The derive option builds the other studio once more per regeneration.
